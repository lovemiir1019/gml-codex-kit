# GameMaker GML

日本語の要望を、対象プロジェクトで使えるGMLと導入手順にする。

## 作業を始める

- [GML共通ルール](references/gml-rules.md)を読む。Chat版にも同じルールを組み込んでいる。
- 既存プロジェクトなら、プロジェクトの指示、引き継ぎメモ、対象の `.yyp` と関連する `.yy` / `.gml` を確認する。複数のゲームがある場合は、対象を特定してから編集する。
- GameMakerのIDE・Runtimeの版、出力先、既存の命名・実装方法を調べる。確認できない情報を推測で確定しない。版によって実装が変わる場合に限って不足情報を聞く。
- 依頼内容を「プレイヤーがどう操作すると、何が起きるか」に直し、必要な範囲を実装する。大きなゲーム全体の依頼は、まず試せる一機能に分ける。

## ファイルを編集する

実際のプロジェクトファイルを変更するときは [プロジェクト編集](references/project-files.md)を読む。
接続済みの公式GameMaker ResourceTool / gm-cliがある場合は、リソース操作に利用できるか調べる。利用環境に存在しないツールを使ったことにしない。
初期設定やツール導入だけを理由に、動いている `.gml` の小さな修正を止めない。

新規の移動サンプルを求められたときだけ [素材なしの移動例](references/movement-example.md)を使う。既存の移動や当たり判定を、サンプルで丸ごと置き換えない。

## 確認して伝える

利用できる既存のビルド・テスト手順で確認する。GameMakerでの実行ができない場合は「実行未確認」と伝え、操作と期待結果を具体的に書く。
返答では、できるようになったこと、変更したオブジェクト・イベント・ファイル、確認結果を日本語で示す。貼り付けが必要なら、追加・置換のどちらかと正確な場所を示す。

## CodexとChatを引き継ぐ

まとまった機能を終えたとき、未解決のエラーがあるとき、または切り替えを頼まれたときは、作業フォルダの `GML_HANDOFF.md` を更新する。
必要項目は [引き継ぎテンプレート](assets/HANDOFF_TEMPLATE.md)を使う。現状と提案を分け、次に試す一手を残す。
Chatへの引き継ぎではメモに加え、対象イベントの現在のコードとエラー全文が必要なことを伝える。まだ適用していない修正を、適用済みとして記録しない。
